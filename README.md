# Instamart Customer Intelligence & Support Copilot

An end-to-end customer intelligence and AI-assisted support automation project built using Python, SQL, Machine Learning, NLP, Retrieval-Augmented Generation (RAG), and tool-calling agents.

## 1. Overview

The Instamart Customer Intelligence & Support Copilot demonstrates how customer data analytics, machine learning, and AI-assisted automation can improve customer understanding and support operations.

The project uses synthetic customer, product, order, support-ticket, and policy datasets. It is organized into four parts.

### Project Objectives

- Build a reliable analytical database from raw datasets.
- Analyze customer purchasing behaviour using RFM analysis.
- Segment customers using K-Means clustering.
- Predict customer lapse risk using machine learning.
- Classify support tickets with privacy and safety guardrails.
- Retrieve relevant policy information using RAG.
- Automate refund-support workflows using a ReAct agent.
- Implement validation, retry handling, token budgeting, human escalation, safe stopping, and checkpoint recovery.

### Technology Stack

|---|---|
| Programming | Python |
| Data processing | Pandas, NumPy |

### Data Auditing and Cleaning

The raw datasets were examined for missing values, duplicate records, invalid values, inconsistent categories, and incorrect data types.

Customer cleaning included:

- Standardizing city names.
- Normalizing gender categories.
- Handling invalid customer ages.
- Imputing missing ages using city-level medians.
- Parsing signup dates.

Order cleaning included:

- Removing 119 exact duplicate rows.
- Resolving repeated order IDs by retaining the latest record.
- Handling pending statuses.
- Repairing invalid order amounts.
- Handling negative and missing delivery durations.

## 4. Part B – Customer Segmentation and Lapse Prediction

### Objective

Understand customer purchasing behaviour, identify customer segments, and predict customer lapse risk using machine learning.

### RFM Analysis

RFM represents:

- Recency: Time since the last completed purchase.
- Frequency: Number of completed purchases.
- Monetary: Total completed-order spending.

A total of 1,175 customers were included in the RFM analysis.

### K-Means Customer Segmentation

K-Means was evaluated for cluster counts from K=2 to K=8. Four clusters were selected.

| Cluster | Customers | Segment |
|---|---:|---|
| 0 | 436 | Occasional Customers |
| 1 | 138 | High-Value Premium Customers |
| 2 | 419 | Loyal Frequent Customers |
| 3 | 182 | At-Risk Dormant Customers |

PCA was used to visualize customer segments.

### Lapse Prediction

The prediction cohort contained:

| Measure | Result |
|---|---:|
| Customers | 1,156 |
| Lapsed customers | 443 |
| Retained customers | 713 |
| Training records | 924 |
| Testing records | 232 |

Numerical scaling and categorical encoding were implemented through a preprocessing pipeline fitted on training data.

### Model Evaluation

Logistic Regression and Random Forest were evaluated using GridSearchCV.

| Model | Accuracy | Precision | Recall | F1-score | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| Logistic Regression | 0.7284 | 0.6444 | 0.6517 | 0.6480 | 0.8011 |
| Random Forest | 0.7414 | 0.6667 | 0.6517 | 0.6591 | 0.7816 |

Random Forest achieved the higher F1-score in the recorded test evaluation and was selected as the final model.

### Oversampling

Oversampling was applied only to training data.

The oversampled Logistic Regression model achieved:

| Metric | Result |
|---|---:|
| Accuracy | 0.7155 |
| Precision | 0.5891 |
| Recall | 0.8539 |
| F1-score | 0.6972 |
| ROC-AUC | 0.7873 |

### Model Persistence

The selected model was saved using Joblib, reloaded, and checked against its original predictions.

A retention list containing 10 Premium customers from the test set was generated.

## 6. Part D – Policy RAG Assistant and Refund Agent

### Objective

Implement a policy-grounded RAG assistant and a simulated refund-support agent using document retrieval, tool calling, ReAct orchestration, safety controls, and checkpoint recovery.

### Policy Document Chunking

Five policy documents are stored under `data/policies/`.

The chunking implementation uses:

- 40-word chunks.
- 10-word overlap.
- TF-IDF vectorization.
- Cosine similarity.
- Top-3 retrieval.

A no-overlap comparison was also implemented.

### RAG Evaluation

The evaluation contains 14 questions:

- 12 answerable questions.
- 2 unsupported questions.

| Metric | With overlap | Without overlap |
|---|---:|---:|
| Document accuracy | 100% | 100% |
| Fact accuracy | 100% | 83.33% |
| Fallback accuracy | 100% | 100% |

Unsupported questions use a fallback response rather than inventing policy information.

### Refund Tools

Five tools are implemented:

1. `get_order`
2. `search_policy`
3. `calculate_refund`
4. `issue_refund`
5. `escalate_to_human`

### Refund Rules

- Only completed orders qualify for refunds.
- Delivery exceeding 45 minutes qualifies for a full order-amount refund.
- Delivery within 45 minutes does not qualify for a late-delivery refund.
- Refunds up to and including INR 1,000 may be issued automatically.
- Refunds above INR 1,000 require human approval.

All refund operations are simulated. No real payment transactions take place.

### Safe Stopping

The implementation demonstrates:

- Token-limit fallback.

## 7. Limitations and Next Steps

### Limitations

1. The datasets are synthetic and do not represent actual Instamart customer or operational data.
2. The language model is simulated using the supplied `mock_llm.py`; the project does not depend on a hosted LLM API.
3. RAG retrieval uses TF-IDF and cosine similarity rather than a production vector database.
4. The RAG evaluation uses a limited benchmark of 14 questions.
5. Refund processing is simulated and does not transfer actual money.
6. Machine-learning evaluation results are specific to the supplied synthetic dataset and are not production performance guarantees.
7. The Premium segment label is a post-hoc descriptive label and should not be interpreted as a leakage-free predictive feature.
8. The agent comparison report does not constitute a separate measured Plan-and-Execute benchmark.

### Next Steps

- Evaluate the models on larger and real-world datasets.
- Integrate a production language model through a secure API.
- Explore vector databases and semantic embedding-based retrieval.
- Expand the policy evaluation benchmark.
- Integrate authenticated support systems and real order-management APIs.
- Add monitoring, logging, and deployment infrastructure.
- Conduct further security, privacy, and performance testing.
