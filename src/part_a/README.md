# Part A — Data Foundation

## Overview

Part A builds the project's data foundation. It audits the supplied synthetic customer, product, order and support-ticket datasets; cleans customer and order data; stores the cleaned tables in SQLite; and runs SQL analysis with Pandas cross-checks.

## Source files

| File | Responsibility |
|---|---|
| `pipeline.py` | Raw-data audit, customer/order cleaning, SQLite database creation and validation |
| `analyze_sql.py` | Executes the seven SQL queries and produces Pandas cross-checks/analysis |
| `validate_data.py` | Runs validation checks against the generated data and database |

## Inputs

The pipeline reads these generated files from `data/raw/`:

- `customers.csv`
- `products.csv`
- `orders.csv`
- `tickets.csv`

The datasets are synthetic and are generated by the project-level `generate_data.py` script. Part A also uses `sql/queries.sql` for its seven SQL queries.

## Processing

### 1. Raw-data audit

The audit records dataset shapes, data types and missing-value counts. It also measures duplicate order rows, pending order rows, distinct order IDs, non-numeric order amounts, negative/blank delivery durations, invalid or blank customer ages, and inconsistent city/gender spellings.

### 2. Customer cleaning

The customer pipeline standardizes city names, normalizes gender categories, treats ages outside the configured valid range as invalid, imputes missing ages using the median for the corresponding city, and parses signup dates.

### 3. Order cleaning

The order pipeline parses timestamps and numeric values, removes exact duplicate rows, resolves repeated order IDs by retaining the latest record, handles pending statuses, repairs unparseable order amounts using product/quantity/discount information, and handles invalid or missing delivery durations. Completed-order delivery times are imputed using the completed-order median for the corresponding product category; cancelled orders retain missing delivery durations.

### 4. Database creation

The cleaned customer, product and order datasets are written to `data/instamart.db` as the `customers`, `products` and `orders` tables.

### 5. SQL analysis and Pandas cross-checks

`analyze_sql.py` executes the seven statements in `sql/queries.sql`, then calculates additional summary statistics, grouped results, pivot/correlation analysis and writes a JSON analysis report.

## Run commands

Run these commands from the repository root, in order:

```bash
python generate_data.py
python run_part_a.py
python -m src.part_a.analyze_sql
python -m src.part_a.validate_data
```

`generate_data.py` regenerates the synthetic raw datasets. `run_part_a.py` runs the audit, cleaning, database creation and pipeline validation. The remaining commands perform SQL/Pandas analysis and validation.

## Notes

- Run Part A before Parts B, C and D because later parts use its generated data/database.
- The data is synthetic; results are not claims about real Instamart customers or operations.
- Run commands from the repository root so the relative project paths resolve correctly.
